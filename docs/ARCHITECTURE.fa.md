# معماری و قراردادها

`validate.py` ورودی CLI است. `patchlab/validate.py` تنظیمات، ساخت و هماهنگی مراحل را مدیریت می‌کند.
`runner.py` فرایندها را بدون shell اجرا و نتیجه را به exit_code، signal، stdout، stderr، timed_out،
error_type، detection_mechanism، frames و signature تبدیل می‌کند.
`evidence.py` کوچک‌سازی، readelf، ارتباط Diff و بستهٔ بازتولید را پیاده می‌کند.

## پیکربندی

مسیرهای نسبی source نسبت به ریشهٔ مخزن هستند؛ مسیر مطلق هم پشتیبانی می‌شود.
دستور ساخت فهرست آرگومان است، نه متن shell. جایگزین‌های `{source}` و `{binary}` دارد.
run.argv فهرست آرگومان با جایگزین‌های `{binary}`، `{input}` و `{input_file}` است.
mode برابر argv، file یا stdin است. در حالت file مسیر ورودی را با `{input_file}` بدهید.
در حالت stdin دادهٔ باینری مستقیماً به stdin فرستاده می‌شود.
ورودی آزمون می‌تواند input متنی، hex باینری یا input_repeat به شکل [رشته، تعداد] باشد.
انتظار هر آزمون شامل expected_exit و expected_stdout است.

در غیر این صورت، پس از تکمیل بررسی‌ها: ۰.

Fixed یعنی خطای پایه در ورودی آزموده‌شده پس از وصله دیده نشده و رفتار مورد انتظار ورودی برقرار است.
Incomplete Fix یعنی امضای قبلی باقی است. New Issue یعنی امضای خطا روی وصله مشاهده شده و همان امضا
در بازپخش پایه مشاهده نشده است؛ این برچسب، علت‌بودن وصله را اثبات نمی‌کند.
Functional Regression از مرجع مستقل به دست می‌آید و از نتیجهٔ امنیت مستقل است.
